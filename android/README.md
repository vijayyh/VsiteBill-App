# SiteVerify Android app

A **Trusted Web Activity** generated by Google's [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap):
a small Android app that opens the live site (`https://vsitebill-app.onrender.com`) full-screen in
Chrome. It contains no copy of the web app's code, so the app always matches the website exactly,
and **every push to `main` reaches the Android app too**, with no reinstall.

A new APK is only needed when `twa-manifest.json` changes (name, colours, version) or the app icon
changes. The launcher icon and the native splash image are copied into the APK from the live
site's `pwa-maskable-512.png` and `pwa-512.png` when `bubblewrap update` runs, so push new icons
first, then regenerate and build. Always raise `appVersionCode` so phones accept the update.

**Opening sequence:** Android shows the native splash (`pwa-512.png` at 300 dp on navy
`backgroundColor`), then the web page takes over. The web splash's first frame is identical (see
`frontend/index.html`), so the handover is seamless, then it animates.

## What's in this folder

| Path | What it is |
|---|---|
| `twa-manifest.json` | The app's settings: app id, name, colours, icons, start page, version. **Edit this**, then regenerate. |
| `app/`, `build.gradle`, `settings.gradle`, `gradle*` | Android project generated from `twa-manifest.json` by `bubblewrap update`. Don't edit by hand. |
| `store_icon.png` | 512 px icon for a Play Store listing. |
| `*.apk`, `*.aab` | Build output. Git-ignored; delivered separately. |

## Key facts

- **App id:** `in.sustaniq.siteverify`. It can't change once the app is published.
- **Website link:** the site proves it owns this app with
  `frontend/public/.well-known/assetlinks.json` (the signing key's SHA-256 fingerprint). That file
  has to live in the website, not here. If it's missing or wrong, the app still works but shows a
  browser address bar.
- **Signing key:** kept **outside the repo**, at `C:\Users\vijay\SiteVerify-android-signing\` on the
  home machine (`siteverify-release.jks` + `PASSWORD.txt`). Never commit it. Every update must be
  signed with this exact key, so keep a backup and copy it securely to any machine that builds.

## Rebuilding

Needs JDK 17 and the Android SDK with build-tools 36.1.0. Bubblewrap also expects the SDK's
command-line tools copied to `<sdk>/tools` (from `<sdk>/cmdline-tools/latest`).

Run from **PowerShell**, not Git Bash (from Git Bash, `gradlew.bat` isn't found):

```powershell
npm install -g @bubblewrap/cli
bubblewrap updateConfig --jdkPath "<JDK 17 folder>" --androidSdkPath "<Android SDK folder>"
cd android
# First bump appVersionCode (and appVersionName) in twa-manifest.json, then:
bubblewrap update --skipVersionUpgrade
$env:BUBBLEWRAP_KEYSTORE_PASSWORD = "<from PASSWORD.txt>"; $env:BUBBLEWRAP_KEY_PASSWORD = $env:BUBBLEWRAP_KEYSTORE_PASSWORD
bubblewrap build --skipPwaValidation
```

Output: `app-release-signed.apk` (install directly on phones) and `app-release-bundle.aab` (upload
to Google Play).

## Installing and first launch

- Send the APK to the phone and tap it. Android asks once to allow installing from that source.
- The first photo asks to allow "Chrome" to use the camera. That's expected, because the app runs
  on Chrome's engine.
- A phone that has never opened Chrome shows Chrome's welcome screen once.

## iPhone

There is no iPhone project. iPhones install the web app itself: open the site in **Safari** →
Share → **Add to Home Screen**. A real App Store app would need a Mac with Xcode and an Apple
Developer account ($99/year).
